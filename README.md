# PM FAQ

> Практическая база знаний для тех, кто делает продукты, принимает решения в условиях неопределённости и старается не утонуть в бэклоге.

**PM FAQ** — открытый справочник о работе продуктового менеджера. Здесь собраны короткие и содержательные ответы на вопросы, которые возникают на старте карьеры и продолжают возникать после нескольких лет в профессии: какую ценность PM приносит команде, как исследовать пользователей, проверять гипотезы, работать с метриками, влиять без прямого подчинения и принимать решения, когда полной информации всё равно не будет.

В основе PM FAQ — простой взгляд на профессию: продакт не «шеф над командой» и не фабрика фичей. Его задача — связывать потребности пользователей, цели бизнеса и технические возможности, помогая команде понимать, **что**, **зачем** и **для кого** она создаёт.

Это не универсальный учебник, не линейный курс и не коллекция магических фреймворков. Материалы дают ориентиры, инструменты и примеры, которые помогают разобраться в ситуации, задать правильные вопросы и принять более осмысленное решение.

## Кому пригодится PM FAQ

- **Тем, кто присматривается к профессии** — чтобы понять, чем на самом деле занимается продакт и подходит ли такая работа.
- **Начинающим PM** — чтобы быстрее освоиться с исследованиями, гипотезами, метриками, командными процессами и бесконечной неопределённостью.
- **Специалистам из смежных ролей** — аналитикам, маркетологам, дизайнерам, разработчикам и project-менеджерам, которые хотят перейти в продукт или лучше понимать коллег-продактов.
- **Практикующим продуктовым менеджерам** — как справочник перед интервью, исследованием, приоритизацией, сложным разговором или очередным спором о том, какую фичу делать первой.
- **Командам и руководителям** — чтобы синхронизировать ожидания от роли PM и говорить о продуктовой работе на одном языке.

## Что внутри

109 материалов объединены в семь последовательных глав:

1. **Роль продуктового менеджера** — ценность PM, специализации, мифы о профессии и качества сильного продакта.
2. **Вход в профессию** — образование, первый опыт, pet-проекты, резюме, портфолио и собеседования.
3. **Продуктовое мышление** — ценность для пользователя, системный взгляд, эмпатия и работа с неопределённостью.
4. **Пользователь и гипотезы** — исследования, интервью, генерация идей, MVP, проверка решений и обратная связь.
5. **Работа с командой** — лидерство без формальной власти, доверие, процессы, синхронизация и конфликты.
6. **Метрики и аналитика** — выбор показателей, источники данных, вовлечённость, бизнес-метрики и интерпретация результатов.
7. **Приоритизация и решения** — фокус, сравнение альтернатив, документирование и проверка принятых решений.

Каждый материал доступен как отдельная страница с заголовком, форматированием и ссылкой на исходную публикацию в Telegram. По базе можно перемещаться через оглавление, поиск, навигацию между соседними статьями и блок тематически связанных материалов.

## Как пользоваться

- Откройте [базу знаний](https://rutboy.github.io/pm_faq/) и найдите вопрос через поиск или тематическое оглавление.
- Читайте отдельную статью, если нужен быстрый ответ, или проходите главы последовательно, если хотите собрать целостное представление о профессии.
- Используйте материалы как отправную точку для обсуждения с командой, подготовки к интервью или разбора конкретной продуктовой ситуации.
- Переходите к оригиналу в Telegram, если нужен контекст публикации или обсуждение в канале.

## Структура проекта

- `index.html` — оглавление, поиск и аккордеоны;
- `posts/<id>/index.html` — отдельные страницы 109 материалов;
- `assets/post.css` — общие стили страниц материалов;
- `assets/social-card.jpg` — карточка 1200×630 для Open Graph и социальных превью;
- `404.html` — полезная страница для несуществующих адресов;
- `content/pm-faq.md` — канонический Markdown с текстами 107 материалов;
- `content/extras/*.html` — два дополнительных текста, которых нет в Markdown;
- `content/post-metadata.json` — даты и ID исходных Telegram-публикаций;
- `scripts/generate-post-pages.py` — генератор статических страниц без внешних зависимостей;
- `sitemap.xml` — главная страница и все материалы;
- `_config.yml` — исключает исходники и служебные файлы из публикации GitHub Pages.

Сайт не требует сборщика или внешних зависимостей. Для локального просмотра достаточно запустить в корне репозитория:

```bash
python3 -m http.server 8000
```

После этого сайт будет доступен по адресу http://localhost:8000/.

## Обновление страниц

Все необходимые тексты и метаданные уже находятся в репозитории. Генератор использует только стандартную библиотеку Python:

```bash
python3 scripts/generate-post-pages.py
```

При обновлении Telegram-источников можно передать каталог с сохранёнными widget-страницами в формате `pmfaq-<id>.html`. Генератор обновит даты и дополнительные тексты:

```bash
python3 scripts/generate-post-pages.py \
  --telegram-dir "/path/to/telegram-cache" \
  --lastmod YYYY-MM-DD
```

Другой Markdown-файл можно проверить через `--source-md`. Каноническую версию для последующих автономных сборок следует сохранить как `content/pm-faq.md`. После содержательных изменений передайте их дату через `--lastmod YYYY-MM-DD`; она сохранится в метаданных, а обычные повторные сборки не будут искусственно менять даты всех страниц.

Результат — обычные HTML-файлы, которые GitHub Pages публикует из ветки `main`. Исходный Markdown и генератор остаются доступны в репозитории, но не попадают в опубликованную версию сайта и не создают дубли страниц.
